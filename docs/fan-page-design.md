# ファンページ（支援ページ）設計

## 背景と目的

アンクラスPort（福岡J・アンクラス公認アプリ）の公開後、Android版の要望が増えた。しかし開発者ライセンス料と開発時間のコストが個人負担では見合わない。そこで開発者個人のファンページを作り、OFUSEメンバーシップを軸に継続的な資金を確保する。

このページの目的はひとつに絞る。

> 「Android版アンクラスPortを実現するための、継続支援を集める」

目的を一点に絞るのは、抽象的な「個人開発を応援してください」より、具体的なゴールのほうが支援率は高いため。既存ポートフォリオの Support セクションは汎用の応援窓口として残し、本ページは目的特化型として独立させる。

## ターゲットと来訪経路

| ターゲット | 状況 | 来訪経路 |
| --- | --- | --- |
| Android利用のアンクラスファン | アプリを使いたいのに使えない。支援動機が最も強い | クラブ関連SNS、note、検索 |
| iPhone版の既存利用者 | 無料・広告なしの恩恵を受けている。返報性が働く | アプリのサポートページ、App Store |
| 開発活動のファン | note・Zenn・GitHubの読者 | ポートフォリオ、記事末尾リンク |

## 位置づけ（既存方針との整合）

`docs/monetization.md` の方針を次のとおり更新する。

- 変更: 主導線をファンレターからメンバーシップに変える（継続資金の確保が目的のため）
- 維持: 支援先は開発者個人であり、クラブへの寄付ではないことを明記する
- 維持: クラブや選手の限定情報を特典にしない
- 維持: 月1回の活動報告
- 変更: 「支援金額を前面に出さない」は本ページでは緩和し、必要コストの内訳と目標人数は開示する（透明性が信頼につながるため）

## サイト構成

```
/                    ポートフォリオ（既存。#support から新ページへ誘導）
/support/            ★新規: ファンページ（本設計の対象）
/anclas-port/        アプリサポート（既存。支援導線を1行追加）
/anclas-port/privacy/ 既存のまま
```

独立URLにする理由: SNS・note記事・アプリ内から直接リンクでき、目的特化のメッセージだけを載せられるため。

## ページ構成（/support/）

上から順に「共感 → 納得 → 行動」の流れで並べる。

### 1. ヒーロー

- 見出し例: 「アンクラスPortのAndroid版を、一緒に実現しませんか」
- リード: 公認アプリを無料・広告なしで運営していること、Android版の要望が多いことを2〜3文で
- 主CTA: 「月額で応援する」（OFUSEメンバーシップ）
- 副CTA: 「まずは話を読む」（ページ内スクロール）
- ビジュアル: アンクラスPortのアプリアイコン + 順位表スクショ（既存アセット再利用）

### 2. ストーリー（なぜ支援が必要か）

- iPhone版を個人で作り、公認をいただいた経緯
- Android版の要望が増えている事実（数字が出せれば添える）
- 個人開発では費用と時間が壁になっていること
- 3〜4段落。長文にしない

### 3. コストの内訳（透明性）

実費が小さいことを隠さず開示し、最大のコストが開発時間であることを正面から書く。金額を大きく見せると、登録料が25ドルだと知っている読者の信頼を失い逆効果になるため、「実費はわずか、いちばんのコストは充て続ける時間」という構成にする。

| 項目 | 内容 | 規模 |
| --- | --- | --- |
| Google Play デベロッパー登録 | 登録料。初回のみ | 25ドル |
| サーバー費用 | iPhone版の仕組みを使うためほとんど増えない | ごくわずか |
| 開発と維持の時間 | 移植・テスト・審査対応。公開後もOS更新・データ確認・問い合わせ対応が続く | いちばん大きなコスト |

表の下で、月額支援を「この時間をAndroid版に優先して充て続けるための支え」と意味づける。時給換算のような生々しい数字は出さず、「時間」という言葉のまま伝える。使い道は月1回の活動報告で示す。

### 4. マイルストーンと現在地

- サポーター数の現在地（「現在 n人 / 目標 N人」）は、n が 0 のあいだ社会的証明が負に働くため出さない。「最初のひとりから数えていきます」と書き、支援者が付いた時点で現在地の表示を検討する
- 段階目標の例:
  - 第1目標: 継続メンバー N1人 → Android版の開発に着手
  - 第2目標: N2人 → 公開と1年間の維持を確定
- 進捗は静的HTMLに手動で反映し、月1回更新する
- 「確約」と読める表現は使わない。「〜を目指します」「着手の判断基準にします」と書く（未達時・中止時のトラブル回避）

### 5. 支援の方法（3段の階段）

心理的ハードルの低い順に3つ並べ、真ん中の月額を視覚的に主役にする。

| 段 | 方法 | 位置づけ |
| --- | --- | --- |
| 無料 | 感想を送る・SNSでシェアする | 誰でも今すぐできる。参加感の入口 |
| 単発 | OFUSEファンレター | 「一度だけ応援したい」の受け皿 |
| 月額（主役） | OFUSEメンバーシップ | 継続資金の柱。カードUIで最も目立たせる |

- リンク先: https://ofuse.me/akirataniwaki （ファンレター）/ https://ofuse.me/memberships/4761 （メンバーシップ「Akiraの開発室」）

### 6. メンバー特典（OFUSE側の設定）

クラブの限定情報を使わず、開発者自身が出せるものだけで構成する。

| 特典 | 内容 |
| --- | --- |
| 詳しい開発ログ | Xに書ききれない設計の判断や失敗をメンバー向けにまとめる |
| 運営状況の共有 | iPhone版の運営状況とAndroid版の開発状況を、区切りごとに共有する |
| サポータークレジット | 希望者のみ、支援ページのサポーター欄にハンドルネームを掲載 |

「開発ログの先行公開」と「機能リクエストの優先投票」は特典から外した。日々の進み具合はXで公開しており先行公開が成立しないため。投票のほうは運用負担が読めないため。ページ側の特典表記は、必ずOFUSEのプラン説明文と同じ粒度・同じ項目数に揃える（着地先で内容が変わると納得感が落ちるため）。

プランは1つ（月額500円）。ページ側にも「月額500円」と金額を明記する。「ワンコインから」のような下限表現は、複数プランがある誤認を招くため使わない。

### 7. 社会的証明

- サポータークレジット（掲載許可を得た名前のみ）
- 届いた感想・要望の引用（本人の許可を得たもののみ。パラフレーズと引用を区別する）
- 公開直後は空になる。枠だけ並べると「誰も支援していない」が際立つため、見出しとリードで空であることを先に認め、「最初のひとり」を募る文脈に置き換える。実績値をひねり出して埋めない

### 8. 活動報告

- noteの開発記録への導線（最新記事1〜3件を手動掲載）
- 「月1回、進捗を報告します」と更新頻度を宣言する（継続支援の安心材料）

### 9. FAQ

支援を迷う理由をそのまま質問にする。金銭面の不安（使途・解約・中止時）と、iPhone版利用者にとっての意味は必ず入れる。

| 質問 | 回答の要点 |
| --- | --- |
| この支援はクラブへの寄付か | いいえ。開発者個人の開発活動への支援 |
| 集まった支援は何に使われるか | 登録料・サーバー費用・開発と維持の時間。支出時に開発記録で報告 |
| 支援すればAndroid版は必ず出るのか | 確約ではなく、目標達成を着手・継続の判断基準にする |
| Android版はいつごろ公開されるか | 時期は約束しない。第1目標到達時に着手を判断し、見通しが立った段階で書く |
| iPhone版利用者にも関係があるか | ある。同じ土台で動くため、確保できた時間はiPhone版の修正やOS対応にも充てる |
| 中止したときはどうなるか | メンバーシップを終了し以後の課金を止める。経緯も知らせる |
| 解約はいつでもできるか | OFUSEの設定からいつでも解約できる。次の更新日からは課金されない |
| iPhone版は有料になるのか | いいえ。無料・広告なしの方針は変えない |

FAQ は `FAQPage` の JSON-LD を併記し、検索結果からも読めるようにする。

### 10. フッター

- ポートフォリオ、アプリサポートページ、プライバシーポリシー、クラブ公式サイトへのリンク
- 「支援は個人の開発活動に対するものです」の注記を再掲

## 資金が集まりやすくする工夫（設計判断の根拠）

1. 目的の一点集中。「Android版の実現」という具体的ゴールをヒーローで宣言する
2. コストの透明化。何にいくら必要かを表で開示し、支援の納得感を作る
3. 進捗の見える化。サポーター数バーで「あと何人」を示し、自分の1口が効く実感を作る
4. 段階マイルストーン。遠い目標だけでなく、近い第1目標を置いて達成体験を早く作る
5. 3段の階段。無料 → 単発 → 月額の順で心理的ハードルを下げ、月額を主役に配置する
6. 返報性の設計。無料・広告なしで運営してきた事実をストーリーで先に伝える
7. 社会的証明。クレジット掲載と感想引用で「自分以外も支えている」を見せる
8. 定期報告の宣言。月1回の報告を約束し、継続課金の不安を減らす
9. 再訪の仕掛け。試合日・シーズン節目にSNSとnoteで進捗を発信し、ページへ戻す

## 実装方針

- GitHub Pages の静的HTML。新規の解析サービス・JSフレームワークは追加しない（`docs/marketing.md` の方針を踏襲）
- `/support/index.html` + `css/portfolio.css` への追記で構成する
- 進捗バー・サポーター数・note記事リンクは手動更新（月1回の活動報告と同じタイミング）
- OGP画像を用意し、SNSシェア時に目的が伝わるようにする（アプリアイコン + コピーの構成。クラブロゴは使わない）
- 公開後にポートフォリオ `#support` とアンクラスPortサポートページから内部リンクする

## 計測

新しい解析は入れず、次の数字を月1回記録する。

- OFUSEメンバー数（最重要。マイルストーン進捗そのもの）
- ファンレター数と支援付きの割合
- ページへの流入元（OFUSE・App Store Connect・GitHubの参照元情報の範囲で）
- 感想・要望の件数

## リスクと対処

| リスク | 対処 |
| --- | --- |
| 目標未達でAndroid版に着手できない | 「確約」と書かず判断基準として提示。未達時も月1報告で経緯を説明する |
| クラブ公式の支援と誤認される | 全ページに「個人の開発活動への支援」を明記。配色・画像でも公式と誤認させない |
| 特典が負担になり本業の開発が止まる | 特典は開発ログ・クレジット・投票のみに限定し、物品や個別対応は設けない |
| 支援集中後の解約増 | 単発ファンレターの受け皿を残し、月額は無理に引き止めない |

## 実装の順序

1. `/support/index.html` を作成（本設計のページ構成どおり）
2. `css/portfolio.css` に support 用スタイルを追記
3. ポートフォリオ `#support` セクションから新ページへ導線変更
4. `anclas-port/index.html` に支援導線を1行追加
5. OFUSE側のメンバーシップ特典・プラン文面を本設計の内容に合わせて更新
6. OGP画像を作成して公開
