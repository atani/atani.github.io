# ポートフォリオ運用計画

## 伝えること

「好きなものを、使い続けられる形に」を軸にする。ポートフォリオではiPhoneアプリに絞り、完成品だけでなく、作った理由や改善の過程も伝える。

## 主な導線

- ポートフォリオから各製品ページへ移動する
- 各製品ページからポートフォリオの開発者紹介へ戻る
- ポートフォリオからOFUSEプロフィールへ移動する
- 継続支援を希望する人にはメンバーシップも案内する
- 開発の背景や改善を読みたい人にはnoteを案内する
- 技術の詳細を読みたい人にはZennを案内する
- 不具合報告は各プロジェクトの窓口へ分ける

## 公開後の4週間

以下はポートフォリオ公開時の計画。アンクラスPortのOFUSE施策は、末尾の「2026年9月の実行・検証記録」とIssue #18を正とする。未チェック・未記載を未実施とみなさない。

### 1週目

- ポートフォリオを公開する
- OFUSEプロフィールとメンバーシップを公開する
- noteを開発記録の主な発信先として案内する
- アンクラスPortの紹介ページから開発者ページへリンクする

### 2週目

- noteでアンクラスPortを作った理由を紹介する
- noteでSports Photographer Helperが試合前の準備をどう助けるか紹介する

### 3週目

- noteでMatch Notebookの記録が次の作戦につながる流れを紹介する
- 技術的な実装を深掘りする場合だけZennにまとめる
- 欲しいアプリや改善案をファンレターで募集する

### 4週目

- 届いた声から改善した内容をnoteで共有する
- ポートフォリオから各製品への移動数を確認する

### 解析導入前に取れた数字と、取れなかった数字

- OFUSEの人数・収益の初期値は[運用方針](monetization.md#ofuseの基準値2026年9月6日)に記録した。
- 支援ページのHTMLと生成スクリプトには、アクセス解析タグ・クリック記録処理を確認できなかった。デプロイナウの[CLI資料](https://deploy.lolipop.jp/docs/cli.md)の `project logs` はビルドログであり、訪問セッションの集計ではない。管理画面のアクセス解析機能の有無は未確認。
- 現時点ではXの「リンククリック数」を入口側の代替指標として使える。これは支援ページの訪問セッションでも、OFUSEへのクリックでも、加入人数でもない。
- 支援ページの訪問セッション、月額OFUSEリンクを押したセッション、流入元別の数値は未取得。クリック率や加入率を算出せず、計測開始前の値を0で埋めない。
- 計測開始日時、テスト訪問・クリックの受信記録も未取得。リンクが開くことの確認と、解析への記録確認は別作業とする。

この未取得の記録は導入前の履歴として残す。以後の計測方法と公開・受信確認の記録は下記を参照する。

### GA4による支援ページの計測

- 計測先：`atani` アカウント内の `atani Support Web`、プロパティ `552898855`、ウェブストリーム `15727591186`、測定ID `G-P79WP49S4Z`。アプリ用プロパティとは分離する。
- 対象：本番の `/support/` と `/support/index.html` のみ。トップページ・アプリ・GitHub Pages・ローカル検証は対象外。
- 同意前はGoogleタグそのものを読み込まない。拒否・JavaScript無効・解析ブロック時も閲覧とOFUSEへの移動を妨げない。同意と解析用Cookieは30日、設定から撤回すると専用Cookieを削除して再読み込みする。
- Googleシグナル、ユーザー提供データ、広告パーソナライズ、拡張計測、詳細な地域・端末データの収集はオフ。タグ側でも広告利用を無効化する。氏名・メッセージ・決済情報・任意のURLクエリやフラグメントは送らない。送信情報とGoogleへの通信についてページ内に説明する。
- 計測対象は**同意した訪問のうち、実際に解析へ届いた範囲**。未同意・拒否・ブロッカーなどによる欠測は推計で補完しない。イベント数を訪問人数や加入数にしない。

| イベント | 意味 |
| --- | --- |
| `page_view` | 同意後のページ表示（1文書につき1回）。GA4のセッション数とは異なる |
| `support_membership_click` | 月額OFUSEへの移動操作。加入完了ではない |
| `support_single_click` | 単発の支援として案内したOFUSEリンクの移動操作 |
| `support_letter_click` | 感想として案内したOFUSEリンクの移動操作 |

単発・感想は同じOFUSE URLだが、押したリンクの案内を区別する。クリックには `support_position`（`hero` / `cards` / `final`）を添える。GA4が標準で生成する `session_start`・`first_visit`・`user_engagement` なども届く場合がある。

#### 発信リンクと週次集計

実験AのX用リンク（未投稿）：

```text
https://atani.lolipop-now.app/support/?utm_source=x&utm_medium=social&utm_campaign=202609-support&utm_content=experiment-a
```

許可する値はコードで限定している。`utm_source` は `x` / `note`、`utm_medium` は `social` / `article` / `profile`、`utm_campaign` は `202609-support`、`utm_content` は `experiment-a` / `experiment-b` / `experiment-c` / `profile` / `qa`。新しい識別子はコードの許可リストとテストを更新してから使う。参照元は既知の公開サイトのoriginだけに縮め、不明な参照元は欠測として扱う。

1. GA4の「探索」で、同じ日付範囲・JSTにそろえた「セッション」指標を使う。行は「セッションの参照元 / メディア」「セッションのキャンペーン」「セッションの手動広告コンテンツ」。
2. 分母は、この支援ページを閲覧した**セッションセグメント**のセッション数。分子は `support_membership_click` を含む**セッションセグメント**のセッション数。同じ訪問での連打・2か所のクリックは1セッションとして扱う。
3. 同じ条件の分子÷分母だけをクリック率とする。「イベント数」「ユーザー数」「Xリンククリック数」を代用しない。標準レポートへの反映前や、セグメントを設定できない間は未取得として残す。
4. OFUSEの新規・支援終了・支援中人数は別途管理画面で記録する。UTMを付けても、外部のOFUSE加入と閲覧を結び付けられるわけではない。
5. 検証用は `utm_source=x&utm_medium=social&utm_campaign=202609-support&utm_content=qa&analytics_debug=1` を付け、DebugViewで確認する。分母・分子の両方から「セッションの手動広告コンテンツ」が `qa` のセッションを除く。検証した9/6は実験期間に含めない。

`Support QA Debug`（デベロッパートラフィック除外）は**テスト状態**で作成した。この段階では通常レポートから自動除外されないため、上記のQAセッション除外を必ず使う。テストデータフィルタ名の反映を確認してから有効化を検討する。反映には24〜36時間かかる場合があり、有効化後の除外は復元できない。[Googleのフィルタ説明](https://support.google.com/analytics/answer/13296662)

公開日時・デプロイID・本番の受信結果は[Issue #18](https://github.com/atani/atani.github.io/issues/18)に追記する。単体・リンク整合テストは `rtk proxy node --test scripts/support-analytics.test.mjs`。ブラウザ検証では、初期状態・拒否保存・再選択、スマートフォン幅とキーボード操作を確認する。画面表示の確認とGoogle側の受信確認を分けて記録する。

実装の根拠：[Googleの同意モード](https://developers.google.com/tag-platform/security/concepts/consent-mode)、[GA4設定項目](https://developers.google.com/analytics/devguides/collection/ga4/reference/config)。同意するまでタグを読み込まないBasic方式を採用した。
